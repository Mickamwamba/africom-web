# Implementation Plan: Events, Trainings & Admin Dashboard

**Branch**: `004-events-trainings-admin` | **Date**: 2026-05-20 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/004-events-trainings-admin/spec.md`

---

## Summary

Add a public Events & Trainings listing with registration, and a role-based admin dashboard (Admin / Staff) to the existing Africom Next.js 14 website. The backend is Supabase (Postgres + Auth + Storage). The admin dashboard lives at `/admin/*` within the same Next.js application — a single Vercel deployment. The existing contact form is extended to also persist submissions to Supabase so the admin can view all inquiries.

---

## Technical Context

**Language/Version**: TypeScript 5 / Node.js 20 (matches existing project)
**Framework**: Next.js 14.2 — App Router, Server Components, Server Actions
**Primary Dependencies**:
- `@supabase/ssr` — Supabase client for Next.js App Router (cookie-based auth)
- `@supabase/supabase-js` — Supabase JS client
- `@tiptap/react` + `@tiptap/starter-kit` — headless rich-text editor for event descriptions
- `@radix-ui/react-dialog` — accessible modal primitive (unstyled, Tailwind-compatible)
- `@radix-ui/react-tabs` — accessible tab primitive for Upcoming/Past toggle
- Tailwind CSS (existing)
- Resend (existing, email)
**Storage**: Supabase Postgres (events, categories, registrations, inquiries, user_roles) + Supabase Storage (event cover images)
**Testing**: Vitest (unit/integration) + Playwright (e2e) — both already configured
**Target Platform**: Vercel (existing deployment target) + Supabase (free tier)
**Project Type**: Web application (Next.js full-stack, single repo)
**Performance Goals**: Events listing page loads in <2s; admin dashboard responses <1s on Vercel Edge
**Constraints**: Supabase free tier (500MB DB, 1GB Storage, 50MB file limit per upload); single Vercel project; no paid add-ons
**Scale/Scope**: <100 events, <1000 registrations, <5 admin/staff users — free tier comfortably accommodates
